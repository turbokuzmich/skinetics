# План первичных SEO-исправлений

Дата фиксации: 19 августа 2026 года. Основание: первичная проверка исходного кода, публичного HTML и данные Яндекс Вебмастера.

## Что уже подтверждено

- В поиске Яндекса участвуют только 8 URL.
- Страницы товаров доступны роботу: отдают `200 OK`, а их title, description и текст доступны без выполнения JavaScript.
- Главная страница в текстовом представлении робота практически пуста: видны навигация и форма, но не каталог и основной контент.
- У индексируемых URL не задан канонический адрес. В истории Вебмастера товарные URL периодически исключались как дубли, а затем возвращались в поиск.
- Sitemap доступен и обработан Яндексом, но содержит 7 URL с устаревшими `lastmod` от 28 ноября 2024 года. В нём нет `/serum` и `/ingredients`.
- Вебмастер рекомендует добавить meta description. Описание есть у главной и товарных страниц, но отсутствует, в частности, у `/catalog` и `/ingredients`.

## Правила до начала работ

- Не менять URL массово, не удалять старые карточки и не ставить 301-редиректы без таблицы «старый URL → целевой URL → причина».
- Не отправлять сайт на массовый переобход до окончания первых пяти пунктов ниже.
- Любой URL, который остаётся в поиске, должен иметь один предпочтительный адрес: `https`, выбранный вариант слеша в конце URL, `200 OK`, self-canonical, внутренние ссылки и запись в sitemap в одном и том же виде.

## Порядок исправлений

### 1. Установить канонические URL и устранить реальные дубли

**Приоритет:** P0

**Что сделать**

- Задать `metadataBase` и `alternates.canonical` в метаданных Next.js для главной, разделов и каждой товарной страницы.
- Выбрать и закрепить единое написание URL: HTTPS, домен без альтернативного зеркала и единая политика завершающего слеша.
- Проверить, что `canonical` указывает на саму индексируемую страницу, а не на главную или другой товар.
- Для снятого товара применять `301` только на действительно эквивалентный актуальный товар или релевантную категорию. Если аналога нет, сначала сохранить полезную информационную страницу либо принять отдельное решение после анализа ссылок и спроса.

**Почему это нужно**

Яндекс уже фиксировал товарные страницы как дубли, а в текущей версии сайта канонический адрес не указан. Без предпочтительного URL поисковая система может поочерёдно выбирать разные версии страницы или исключать её из выдачи. Это создаёт нестабильную индексацию и не даёт накапливать сигналы на одной странице.

**Критерий готовности**

У каждого целевого URL один `rel="canonical"`, совпадающий с фактическим адресом страницы; не остаётся конкурирующих дублей, а история Вебмастера перестаёт показывать их повторяющееся исключение.

### 2. Сделать основной контент главной и разделов доступным в исходном HTML

**Приоритет:** P0

**Что сделать**

- Найти причину, по которой главная страница в текстовом представлении робота не содержит каталог и основной текст, хотя в исходном проекте эти компоненты есть.
- Проверить так же `/catalog`, `/serum`, `/about` и будущие посадочные страницы.
- Важные заголовки, описание категории, карточки товаров и внутренние ссылки должны отдаваться сервером в HTML до выполнения JavaScript.
- Не включать выполнение JavaScript для робота как замену исправлению SSR/рендеринга: у товарных страниц серверный вывод уже работает, а проблема локализована на других маршрутах.

**Почему это нужно**

Главная — ключевая страница бренда и каталога. Если робот видит на ней только навигацию и форму, он не получает достаточно тематического контента и ссылок на товары. В результате главная не передаёт релевантность разделам и хуже участвует в поиске, даже если отдельная товарная карточка технически доступна.

**Критерий готовности**

Проверка страницы в Вебмастере и raw HTML показывают на каждой важной странице её H1, текст, карточки/ссылки и метаданные без выполнения JavaScript.

### 3. Заменить ручной sitemap на автоматически формируемый

**Приоритет:** P0

**Что сделать**

- Генерировать `sitemap.xml` из актуального списка индексируемых страниц и товаров, а не поддерживать XML вручную.
- Включать только URL, которые должны участвовать в поиске и уже прошли правило из пункта 1.
- Добавить актуальные `/serum` и другие разрешённые к индексации разделы; не добавлять заготовки и удалённые товары.
- Заполнять `lastmod` только фактической датой содержательного изменения страницы; не подставлять искусственную ежедневную частоту обновления.

**Почему это нужно**

Текущий sitemap успешно читается Яндексом, но содержит только 7 ссылок и давно не обновлялся. Он не является причиной всех проблем сам по себе, но не помогает роботу находить актуальную структуру, новые карточки и изменения ассортимента. После каноникализации sitemap должен сообщать роботу именно тот набор URL, который бренд хочет видеть в поиске.

**Критерий готовности**

В sitemap нет URL с редиректом, `noindex`, дублей и 404; каждый URL совпадает с canonical. Вебмастер обрабатывает файл без ошибок и видит ожидаемое число ссылок.

### 4. Доработать title и description точечно, а не массовой заменой

**Приоритет:** P1

**Что сделать**

- Добавить уникальные title и description для `/catalog` и `/ingredients`, когда для `/ingredients` появится полноценный контент.
- Проверить главную, `/about`, `/contacts`, `/serum` и карточки товаров на уникальность и соответствие реальному содержимому.
- Убрать из сниппетов неподтверждённые обещания и географию «в Москве», если фактически предложение рассчитано на продажи по России через Wildberries.
- Не переписывать уже работающие метаданные лишь ради вставки ключевых слов.

**Почему это нужно**

Яндекс показывает актуальную рекомендацию об отсутствующих description. На части важных страниц описание действительно не задано. Хороший title и description помогают роботу понять назначение страницы и пользователю выбрать результат, но не компенсируют отсутствие контента, canonical и индексации — поэтому задача выполняется после P0.

**Критерий готовности**

У каждой индексируемой страницы уникальные и правдивые title и description; после повторной проверки рекомендация Вебмастера исчезает или не относится к целевым URL.

### 5. Провести ревизию товарных текстов и рекламно-медицинских утверждений

**Приоритет:** P0 для комплаенса, P1 в технической последовательности

**Что сделать**

- Составить список всех утверждений о лечении, профилактике заболеваний, гарантированном результате, безопасности и воздействии на фолликулы/клетки.
- Сверить каждое утверждение с маркировкой, составом, документами на продукт и согласованной юридической позицией бренда.
- Переписать неподтверждённые формулировки в аккуратный язык косметического ухода: назначение, способ применения, ингредиенты, ограничения и реалистичные ожидания.
- Отделить материал об ингредиентах от обещаний конкретного продукта и добавить честные предупреждения о индивидуальной реакции.

**Почему это нужно**

На действующих карточках встречаются фразы вроде «полностью безопасен», «эффективность доказана», «пробуждает спящие фолликулы», «тормозит появление седины». Они создают регуляторный и репутационный риск, снижают доверие к каталогу и выглядят как устаревший SEO-копирайтинг. Технически их можно исправлять параллельно с пунктами 1–3, но публиковать без проверки доказуемости нельзя.

**Критерий готовности**

Каждое оставшееся существенное обещание имеет подтверждение, а карточка содержит понятное описание назначения, состава, способа применения, ограничений и переход на Wildberries.

### 6. Проверить результат, затем отправить ограниченный набор страниц на переобход

**Приоритет:** P1

**Что сделать**

- После развёртывания проверить raw HTML, HTTP-код, `robots`, canonical, title и description для `/`, `/catalog`, `/serum` и всех трёх товарных карточек.
- В Яндекс Вебмастере проверить эти же URL инструментом «Проверка страницы».
- Отправить на переобход только изменённые ключевые URL: главную, каталог, `/serum`, карточки товаров и sitemap.
- Через 2–4 недели сопоставить число страниц в поиске, исключения, показы, клики и запросы с исходной точкой.

**Почему это нужно**

Переобход не исправляет технические причины сам по себе, но после исправления сокращает время ожидания нового обхода. Ограниченный список не создаёт лишнего шума и позволяет связать изменение результата с конкретным релизом.

**Критерий готовности**

Изменённые URL успешно проходят проверку, не исключаются как дубли, sitemap обработан, а динамика индексируемых страниц и показов зафиксирована в отдельной точке контроля.

## Вне этого релиза

- Регион Яндекса не назначать, пока не принято бизнес-решение: сайт ориентирован на локальную консультацию в Москве или на федеральные продажи через Wildberries.
- Яндекс Бизнес подключать только при наличии подтверждаемой точки присутствия и цели получать обращения из Карт.
- Новые страницы по проблемам кожи головы и ингредиентам создавать после сбора семантики, оценки спроса и подготовки качественного контента; не делать массовую генерацию URL.
